# 协议说明

> 本文档仅供**研究与互操作**参考。它不是厂商官方文档，
> 也不包含厂商的任何代码或资源 —— 以下内容是通过观察设备与主机之间公开的
> USB HID 通信整理出来的。详见仓库根目录的 [DISCLAIMER.md](../DISCLAIMER.md)。

本文描述的是 [mouse.pink](https://mouse.pink/) / mouse.xyz 网页驱动所用的设备协议。
这些设备在 Windows 里**没有系统级的电量属性**，所以任何"读取系统设备属性"的通用工具
都读不到电量 —— 真正的数据在厂商自定义的 HID 报文里。

---

## 一、两套协议家族

同一套白牌驱动下存在两套互不相干的协议，**同一只设备只会说其中一套**。
不需要试探性发命令，**看 HID 描述符就能判断**：

| 家族 | 判定依据 | 传输方式 |
|---|---|---|
| **compx** | 输入报文**和**输出报文都是 17 字节 | 报告 ID `8` 的 17 字节中断报文 |
| **feature** | feature 报文 ≥ 65 字节 | 65 字节 feature 报文 |

## 二、compx 协议

### 2.1 帧格式

报告 ID `8` + 16 字节载荷，共 17 字节。最后一个字节是校验：

```
payload[15] = (85 - sum(payload[0..14]) - 8) & 0xFF
```

以"读电量"命令为例：

```
08 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 49
^^ ^^                                              ^^
报告ID=8   命令 0x04 = 读电量                      校验和
```

### 2.2 回复布局

```
raw[0] = 报告 ID
raw[1] = 命令 echo（回显你发的是哪条命令）
raw[2..5] = 参数回显
raw[6..] = 数据
```

> ⚠️ 如果用 WebHID，`event.data` **不包含报告 ID**，
> 所以驱动层代码里的下标比这里的 `raw` 小 1。

### 2.3 命令表

| 命令 | 用途 | 载荷说明 |
|---|---|---|
| `0x01` | 取 EID / 接收器 PR | — |
| `0x04` | **读电量** | → `raw[6]`=电量%, `raw[7]`=充电标志, `raw[8..9]`=电压 mV（大端） |
| `0x05` / `0x06` | 进入配对 / 取配对结果 | — |
| `0x07` | **写 EEPROM** | `[2..3]`=地址（大端）, `[4]`=长度, 数据从 `[5]` 起（单次 ≤ 10 字节） |
| `0x08` | **读 EEPROM** | `[2..3]`=地址（大端）, `[4]`=长度（单次 ≤ 10 字节） |
| `0x09` | ClearSetting | — |
| `0x0E` / `0x0F` | 取当前配置档 / 切换到指定档 | — |
| `0x12` / `0x1D` | 读固件版本 / 带设备号的固件版本 | — |
| `0x16` / `0x17` | 设置 / 读取 LongRange 模式 | — |
| `0x2E` | StartCalibr | — |

### 2.4 ⚠️ 破坏性命令

```
0xB0  = 进入 bootloader（刷固件）
```

**不要发送这条命令。** 除了上表中确认过的读写命令之外，其他命令都不建议尝试。

## 三、EEPROM 地址表

以下是厂商驱动内部使用的地址常量：

| 名称 | 地址 | 说明 |
|---|---|---|
| ReportRate | `0` | 回报率，2 字节 |
| maxDpiStage | `2` | 启用的 DPI 档位数 |
| CurrentDPI | `4` | 当前档位索引 |
| KeyOperation | `8` | 按键开关（SPDT）位域 |
| LOD | `10` | 静默高度 |
| DPIColor | `44` | 指示灯颜色 |
| KeyFunction | `96` | 按键功能映射 |
| DebounceTime | `169` | 去抖时间 |
| SleepTime | `173` | 休眠时间 |
| SensorFPS20K | `225` | 传感器 20K FPS 开关 |
| WheelDebounceTime | `227` | 滚轮去抖 |
| **DPI 表（实际生效）** | **`6912`（0x1B00）** | 见 3.3 |
| ~~DPIValue~~ | ~~`12`~~ | ⚠️ **废弃的旧表，固件不读它**，见 3.3 |

### 3.1 数值编码约定

写入单个数值时，驱动会同时写两个字节：

```
[addr]   = value
[addr+1] = 85 - value      （设备自己维护的补数）
```

所以**偶数地址的下一个字节是它的补数**。按长度 2 写入不会破坏这个约定 ——
设备会自己维护补数字节。

### 3.2 SPDT（左右键开关）

地址 `8` 是一个位域：

| 位 | 含义 |
|---|---|
| bit0 | 左键 SPDT |
| bit1 | 右键 SPDT |

例：只开右键 → `[8] = 0x02`，`[9] = 0x53`（= 85 − 2）。

### 3.3 DPI（灵敏度）

**生效的是 `0x1B00`（十进制 6912）那一片表**，每档 **6 字节**：

```
[X低, X高, Y低, Y高, (高位<<2) | (高位<<6), 校验]
```

- `X` / `Y` 的低 16 位分别放在 `[0][1]` 和 `[2][3]`
- 最高 2 位塞进 `[4]` 的两个 bit2 位置
- 编码值 = **DPI − 1**（即 `code = DPI − 1`）
- 校验字节 = `85 − 前 5 字节之和`（取低 8 位）

对照表：

| DPI | 编码后的 6 字节 |
|---|---|
| 400 | `8F 01 8F 01 00 35` |
| 800 | `1F 03 1F 03 00 11` |
| 1200 | `AF 04 AF 04 00 EF` |
| 1600 | `3F 06 3F 06 00 CB` |
| 2400 | `5F 09 5F 09 00 85` |
| 3200 | `7F 0C 7F 0C 00 3F` |

第 N 档（从 1 开始）的地址是 `6912 + (N-1) × 6`。

> ### ⚠️ 关于地址 12 的陷阱
>
> 地址 `12` 那一片也有一张"看起来完全合理"的表，格式是 4 字节 / 档、步长 50
> （例如 400 是 `07 07 00 47`）。它能读、能写、校验也对，
> **但固件根本不读它** —— 那是废弃的旧数据表。
>
> 判断依据：写入后设备回读一致，但设备行为毫无变化。
> 真正生效的是 `0x1B00` 那一片。
>
> **这个坑的教训是通用的**：固件里常留着废弃的旧数据表，
> "能写进去 + 能读回来" **不等于** "生效"。
> 定位真实地址的可靠办法是**改前改后整片 dump 对比**：
> 把候选区域全读出来 → 只改那一个设置 → 再全读一遍 → 逐字节 diff。
> 真正变化的地址就是它。（`查DPI.bat` 就是干这个的。）

### 3.4 回报率

地址 `0`，2 字节，编码值 = **Hz ÷ 125**：

| 编码值 | 回报率 |
|---|---|
| 1 | 125 Hz |
| 2 | 250 Hz |
| 4 | 500 Hz |
| 8 | 1000 Hz |
| 16 | 2000 Hz |
| 32 | 4000 Hz |
| 64 | 8000 Hz |

## 四、读取注意事项

- **读 EEPROM 单次最多 10 字节**，读更长的区域需要分段。
- 设备有**省电机制**：设备休眠时，收发器可能有 10~15 秒**一帧都不转发**。
  读取失败通常不是程序问题，动一下设备即可恢复。
- **等待 HID 输入报文时不要"超时了就取消 I/O 再重新挂起"** ——
  取消到重新挂起之间的空窗会把回复永久丢失。
  正确做法是耐心等待同一个已挂起的读。（在 Windows 上指 `CancelIo` / `ReadFile` 那一套。）
- 嗅探器（只监听输入报文）**看不到主机发出的写命令**，
  只能从回复里的命令 echo 反推 —— 所以"没抓到某条写命令"不能证明"没写"。

## 六、HID 通用注意事项（Windows）

- 设备接口路径必须带 `\\.\` 前缀；路径里出现 `?` 必然导致 `ERROR_PATH_NOT_FOUND`。
- `SetupDiGetDeviceInterfaceDetail` 传 `NULL` 查询缓冲区大小时，
  **按设计返回 `FALSE`**，这是正常的 —— 只看 `out required` 参数即可。
- 重叠 I/O 的缓冲区与 `OVERLAPPED` 结构**必须放在非托管内存**
  （`AllocHGlobal` + `StructureToPtr`），否则 GC 压缩会让内核写到野地址。
  取消时必须 `CancelIo` 之后再用 `GetOverlappedResult(..., wait: true)` 等它真正结束，
  才能释放那块内存。
